# Generation prompt artifacts

These files are the **verbatim prompt artifacts** for the generative stratum of the
dataset. They are committed as files, not merely embedded as strings in a manifest,
so they can be reproduced in the paper's appendix and diffed across runs.

`scripts/generate-dataset.ts` **loads these files from disk at run time**. It does not
contain a second copy of any prompt text. The file committed here is therefore
provably the text that was sent to the model, and the manifest records the SHA-256 of
each file alongside its content so any later edit is detectable.

| File | Role |
|---|---|
| `system-instruction.md`      | System instruction, constant across every request. |
| `generation.template.md`     | First-attempt user prompt. Placeholders `{{...}}` are substituted per item. |
| `corrective-retry.template.md` | Follow-up prompt used when a generated payload misses its target byte band. |
| `response-schema.json`       | `responseSchema` passed to the API, constraining decoding to the canonical shape. |

## Fields deliberately absent from the response schema

Three fields are **assigned by the pipeline, never generated by the model**:

- `id` — assigned from the reserved generated-ID namespace (9000001+), so a generated
  payload can never carry an identifier that collides with, or is mistakable for, a
  Spoonacular recipe ID.
- `image` — set to `generated://dishcovery/<id>.jpg`. Deliberately not an `http(s)`
  URL so it cannot be mistaken for a real Spoonacular image reference.
- `extendedIngredients[].id` — assigned as `90000 + index`, for the same reason as
  `id`: the model must not emit values that look like real Spoonacular ingredient IDs.

Every other field is model-generated.
